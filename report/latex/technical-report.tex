% --- Module -----------------------------------------------------------------
\newpageheading{2. Module and benchmark}{What is being optimized}

The evaluated module is a sequential implementation of SHA-1 compression from the public
\href{https://github.com/verilog-to-routing/vtr-verilog-to-routing}{Verilog-to-Routing repository}. The exact upstream source is the
\href{https://github.com/verilog-to-routing/vtr-verilog-to-routing/blob/95f5c6de9e158371ba7185bf97c07a84153735d6/vtr_flow/benchmarks/verilog/sha.v}{pinned \texttt{sha.v} at commit \texttt{95f5c6de…}}.

It consumes a 512-bit message block through a 32-bit command/data interface and updates a 160-bit chaining state through 80 rounds of Boolean mixing, rotations, a message schedule and modulo-$2^{32}$ addition. A legal block occupies 80 busy cycles.

\begin{lstlisting}[language=VerilogDiff]
module sha1(clk_i, rst_i, text_i, text_o, cmd_i, cmd_w_i, cmd_o);
  input clk_i, rst_i, cmd_w_i;
  input  [31:0] text_i;
  output [31:0] text_o;
  input  [3:0]  cmd_i;
  output [3:0]  cmd_o;
endmodule
\end{lstlisting}

Only \texttt{sha.v} may change. Reset behavior, command protocol, digest read order, latency, throughput and every observable cycle remain fixed. SHA-1 is a useful public vehicle for the method because it combines sequential control, word-level arithmetic and nonlinear Boolean logic; it is not recommended here as a security primitive.

\subsection{Why the two expressions are equivalent}
\begin{align*}
F &= BC \oplus (\neg B)D \\
  &= BC \lor (\neg B)D \\
  &= (B \lor D)\bigl((\neg B) \lor C\bigr).
\end{align*}
The products $BC$ and $(\neg B)D$ are mutually exclusive because $B$ and $\neg B$ cannot both be one, so their XOR equals OR. Expanding the accepted product-of-sums gives $BC \lor (\neg B)D \lor CD$. The $CD$ consensus term is redundant: when $C=D=1$, either $B=1$ makes $BC$ true or $B=0$ makes $(\neg B)D$ true. Both forms therefore select $C$ when $B$ is one and $D$ otherwise.

\begin{claimbox}\textbf{Formal result.} EQY proved this identity in the complete sequential circuit. The diagram is conceptual; the FPGA mapper remains free to choose the final LUT implementation.\end{claimbox}

\subsection{Why the two expressions are equivalent}
\begin{align*}
M &= BC \oplus CD \oplus BD \\
  &= BD \oplus C(B \oplus D) \\
  &= BD \lor C(B \oplus D).
\end{align*}
The first two lines are the same XOR polynomial after factoring $C$ from $BC \oplus CD$. The terms $BD$ and $B\oplus D$ cannot both be one: if $BD=1$, then $B=D=1$ and $B\oplus D=0$. Their XOR can therefore be replaced by OR. If $B$ equals $D$, their shared value decides the majority; if they differ, $C$ decides it.

\begin{claimbox}\textbf{Formal result.} EQY proved the actual Verilog implementations equivalent over the complete sequential design.\end{claimbox}

\subsection{Why the two expressions are equivalent}
\begin{align*}
X &= W_{13}\oplus W_8\oplus W_2\oplus W_0 \\
  &= (W_{13}\oplus W_8)\oplus(W_2\oplus W_0).
\end{align*}
Bitwise XOR is associative at every bit position, so regrouping changes no result bit and introduces no carry. The parentheses expose two parallel first-level operations before the final XOR. A synthesizer may rebalance the baseline itself, but explicit grouping can influence intermediate optimization, LUT packing and routing topology.

\subsection{Why the two expressions are equivalent}
\begin{align*}
S &= (R+f+E+K_t+W_t)\bmod 2^{32} \\
  &= \bigl((R+f)+(E+K_t+W_t)\bigr)\bmod 2^{32}.
\end{align*}
Every operand and the assigned result is a 32-bit unsigned vector. Addition is associative modulo $2^{32}$: discarding an overflow carry at an intermediate grouping cannot change the final low 32 bits. The accepted form changes the exposed dependency structure, not the numerical result. This identity depends on the declared widths and unsigned vector semantics.

% --- Environment ------------------------------------------------------------
\newpageheading{10. PPA environment and statistics}{Open 45 nm FPGA proxy}

The target is VTR's homogeneous \texttt{k6\_N10\_I40\_Fi6\_L4\_frac0\_ff1\_45nm} architecture: six-input LUTs clustered ten per logic block, with the architecture's routing and timing model. Power uses VTR PTM45 properties at 0.9 V and 85 °C. MWTA is a minimum-width-transistor-area abstraction, not physical square-micrometer area.

Two 5,000-cycle ACE traces are frozen and hashed. The active trace continuously executes diverse legal blocks and completes 60 blocks; the idle trace keeps the clock active after reset with an inactive interface. Both power analyses reuse the same placement and route.

\[
E_{\text{block}}=
\frac{P_{\text{active,total}}\;t_{\text{routed workload}}}{60\ \text{completed blocks}}.
\]

Baseline and accepted RTL use the same 64 VPR seeds. Ratios are analyzed in log space because PPA comparisons are multiplicative. For seed $s$:
\[
r_s=\sqrt[3]{r_{A,s}\,r_{D,s}\,r_{E,s}},
\qquad
\widehat r=\exp\!\left(\frac{1}{64}\sum_{s=1}^{64}\log r_s\right).
\]

Two-sided 95\% Student-$t$ intervals use 63 degrees of freedom. The baseline is exactly 1.0 in paired-ratio space by construction, so baseline and accepted seed clouds are instead normalized to the same baseline median in the next figure. This preserves baseline variability and makes the physical displacement of the accepted cloud visible on one axis.

\begin{scopebox}
\textbf{Decision rule.} Every correctness and integrity gate must pass; at least one primary metric must improve materially; no primary metric may show statistical evidence of regression; and the composite one-sided 95\% upper bound must remain below 1.0.
\end{scopebox}

\newpageheading{14. Limits and customer transfer}{What this result does and does not establish}

This report does not provide:
\begin{itemize}
  \item ASIC synthesis, place-and-route or signoff;
  \item commercial-FPGA implementation data;
  \item extracted parasitics, PVT corners, clock-tree signoff, IR drop, EM, DRC/LVS, package, yield or production-test analysis;
  \item proof that the same source edits improve another architecture, technology or workload;
  \item exact PPA attribution to an individual rewrite;
  \item a recommendation to use SHA-1 in a new security design.
\end{itemize}

The 64-seed confidence interval models implementation-seed variability. It does not model process, voltage, temperature, workload or tool-version uncertainty.

\begin{claimbox}
\textbf{Transfer to a customer pilot.} Replace the academic proxy with customer-owned RTL, formal strategy, libraries, constraints, activity, tools and signoff policy. The transferable capability is the combination of a small inspectable source change and an evaluator that can justify acceptance to the engineers responsible for the system.
\end{claimbox}
